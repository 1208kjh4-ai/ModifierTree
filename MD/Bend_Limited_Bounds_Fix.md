# Limited Bend의 구간 밖 폭 오판 수정 — 0.15.4

## 증상과 원인

좁은 통로에 넓은 가지가 연결된 전체 객체는 Bend 결과가 나오지 않지만, 좁은 구간만 따로 만든 객체는 같은 굽힘에 성공하는 사례를 조사했다. 사용자 파일의 실패 메시지는 아직 확보하지 못했으나, 코드에서 이 차이를 일으킬 수 있는 보수적 오판을 확인했다.

이전 안전 검사는 입력 Brep 전체의 Bend 로컬 bounding box를 사용했다. Limited 길이 구간과 일부라도 겹치면, 구간 밖 넓은 가지의 X 극값도 안쪽 붕괴 검사에 포함됐다. Limited 구간 밖은 아래쪽이 항등 변형, 위쪽이 끝 접선의 강체 변형이므로 그 부분의 폭으로 굽힘 구간의 붕괴를 판정하면 안 된다.

예를 들어 높이 100, Strength +90°의 곡률 반지름은 약 63.66이다. 굽힘 구간 안은 X=-5~5인 좁은 통로이고 Y=120~130의 가지가 X=80까지 뻗은 단일 Brep이면, 기존 검사는 X=80으로 붕괴를 판정했다. 실제로 구부러지는 좁은 부분의 X 최대는 5다. 이 수치는 설명용이며 사용자 모델의 치수를 측정한 것은 아니다.

## 변경 방식

- 전체 bounding box로 이미 안전한 입력은 기존의 빠른 검사를 사용한다.
- 위험한 Limited 입력이 길이 구간 밖까지 이어지면, 검사용 복사본을 로컬 Y=0 및 Y=height 경계 평면으로 잘라 남는 부분의 X 범위를 검사한다. 절단 허용오차로 구간 안의 얇은 부분을 누락하지 않도록 양쪽 경계는 바깥으로 문서 허용오차의 2배만큼 넓힌다.
- 평면 절단의 모든 결과 조각을 검사하고 임시 형상을 해제한다. 입력 객체, GUID, 트리 구조는 분할하거나 교체하지 않는다.
- 입력 전체에는 기존 LengthPreservingBend를 적용한다. 박스 밖의 연결된 부분도 기존처럼 모양을 유지하며 끝단을 따라 이동·회전한다.
- 구간 안의 실제 붕괴, Unlimited의 붕괴 및 한 바퀴 감김 제한, 최종 닫힌 솔리드 검증은 유지한다.
- 검사용 형상 절단이 실패하면 안전하다고 간주하지 않고 `Cannot verify the solid inside the Limited Bend interval...` 오류로 표시한다.

Control Box의 휘어진 선은 계산 성공 여부를 보증하는 표시가 아니다. 이 변경은 표시 방식, 중심 기준, Strength 및 저장 스키마를 바꾸지 않는다. Limited는 계속 로컬 Y 길이 구간이며, X/Z 여섯 면 내부로 변형 범위를 제한하는 기능이 아니다.

## 화면 확인

1. 설치 후 Rhino에서 `MTreeStatus` 버전이 `0.15.4.0`인지 확인한다.
2. 이전에 실패한 **전체 연결 객체** 또는 그 Boolean 결과를 Bend의 일반 입력으로 넣는다. Control Box만 자식으로 있는 상태는 입력이 없는 상태다.
3. 같은 Control Box 위치·방향·크기와 Strength 90° / Limited로 결과를 확인한다. 좁은 구간을 따로 잘라 입력할 필요가 없어야 한다.
4. 시작 쪽 형상이 그대로 남고 끝 쪽의 넓은 가지가 모양을 유지하며 굽힌 끝을 따라오는지 확인한다.
5. 박스를 이동·회전하고 Strength 부호를 바꾼다. 확정·Undo·연속 검볼 조작도 확인한다.
6. 넓은 부분을 실제 굽힘 구간에 넣어 붕괴하는 경우에는 계속 오류를 표시해야 한다.

실패하면 `MTreeStatus`에서 Bend의 상태·입력 수·오류를 확인한다. 편집 중 패널의 `Editing`은 계산 오류를 가릴 수 있다. `reaches the curvature center`는 안전 검사, `Cannot verify ... Limited Bend interval`은 검사용 절단, `could not produce a valid closed solid`는 실제 변형 후 형상 검증 실패다.

기존 설치를 `artifacts/install-backups/283ed41ae6e541788b2d8402e39fdfe0`에 백업하고 고정 설치 경로에 0.15.4를 반영했다. 설치된 assembly 버전은 `0.15.4.0`이며 플러그인과 Core DLL 모두 빌드 산출물과 SHA-256이 일치한다.

2026-09-12 Release 빌드 경고·오류 0개, Core 205개 및 RhinoCore를 시작하지 않는 선택 정책·Eto/WPF UI 78개 검사를 통과했다. [빌드 로그](../artifacts/validation/0.15.4/release-build-2026-09-12.txt)와 [UI 검사 로그](../artifacts/validation/0.15.4/ui-checks-2026-09-12.txt)를 보관했다.

구간 밖 가지를 가진 닫힌 단일 Brep, 부호 반전·회전 프레임, 구간 안 실제 붕괴, Unlimited 및 입력 보존의 native 회귀 검사 6개를 추가했고 컴파일을 확인했다. 다만 과거 이 PC에서 전체 RhinoCore 호스트 시작이 `COM E_FAIL` 및 `dotnet.exe` 오류를 발생시켰으므로 같은 호스트를 이번 작업에서는 재실행하지 않았다. 따라서 이 6개 형상 검사는 **미실행**이며 PASS 수에 포함하지 않는다. 사용자 모델의 실제 Bend 성공 여부도 위 화면 확인이 필요하다.
