# Modifier Tree 0.3.0 화면 검증

이번 버전은 빈 Modifier를 생성하고 사용자가 드래그로 순서와 부모·자식 관계를 구성합니다.
Core 등 23개와 Rhino 계산·문서 스냅샷 검사 38개는 통과했습니다. 아래 실제 UI 동작은 별도로 확인해야 합니다.

## 준비

1. 기존 작업을 저장하고 Rhino를 재시작합니다.
2. `artifacts/bin/0.3.0/Release/net8.0-windows/ModifierTree.rhp`를 로드합니다.
3. `MTreeStatus`에서 `0.3.0.0`을 확인합니다.
4. 새 문서에서 겹치는 Box 두 개를 만들고 이름을 `Brep A`, `Brep B`로 지정합니다. Shaded 모드로 시작합니다.
5. `MTree` → **+ Add Object**로 두 객체를 등록합니다.

예시: A는 (0,0,0)~(10,10,10), B는 (5,-1,-1)~(15,11,11)입니다.
A−B는 A의 오른쪽 절반이 잘린 결과, B−A는 B에서 A와 겹치는 부분이 잘린 결과입니다.

## 빈 Modifier와 드래그 편집

- [ ] **+ Add Modifier**를 누르면 목록이 열리고 Boolean Difference를 선택할 수 있다.
- [ ] 생성된 Modifier는 최상위의 빈 행이며 기존 객체를 자동으로 가져가지 않는다.
- [ ] 원본 이름이 `Brep A`, `Brep B`로만 표시되고 역할 접두사가 없다.
- [ ] A를 Modifier 행 위에 드롭하면 자식으로 들어가고 `Needs inputs` 상태가 된다.
- [ ] B도 자식으로 넣으면 위에서부터 A, B 순서에 따라 A−B 결과가 표시된다.
- [ ] B를 A 위의 행 사이로 옮기면 순서와 결과가 B−A로 바뀐다.
- [ ] 다시 순서를 바꾸면 원래 결과로 돌아온다.
- [ ] B를 하단 **Drop here to move to root**에 놓으면 최상위로 빠지고 불완전한 Modifier의 이전 결과가 사라진다.
- [ ] B를 다시 넣으면 결과가 복원된다.
- [ ] Modifier를 접고 펼칠 수 있다.

## 여러 입력과 중첩

- [ ] 세 번째 Box C를 등록하여 마지막 자식으로 넣으면 첫 입력에서 B와 C를 뺀다.
- [ ] 두 번째 빈 Modifier를 생성해도 첫 번째 트리의 구조는 유지된다.
- [ ] 첫 번째 Modifier를 두 번째 Modifier 안에 넣고, C를 두 번째 Modifier의 다음 자식으로 옮길 수 있다.
- [ ] 이 구조에서 (A−B)−C가 계산되고 최상위 결과만 표시된다.
- [ ] Modifier 자신 또는 자신의 자손 안으로 드래그하는 순환 구조는 허용되지 않는다.
- [ ] 중첩 Modifier를 Remove하면 자식들이 상위로 올라오고 Rhino 원본 객체는 남는다.
- [ ] 최상위 객체와 Modifier의 순서도 드래그로 바꿀 수 있다.

## 원본 편집과 표시

기본 A−B 구조로 돌아온 뒤 확인합니다. 원본 행 선택 → **Select in Rhino**로 원본을 선택할 수 있습니다.

- [ ] 청록색 결과와 입력 선이 표시된다. 원본의 채워진 면이 결과를 가리지 않는다.
- [ ] B를 Move/Rotate/Scale1D/Gumball로 조작한 후 결과가 갱신된다.
- [ ] Undo와 Redo 후 각각 원본 형상에 맞게 결과가 복원된다.
- [ ] Move 중 Esc로 취소하면 원본과 결과가 이전 상태를 유지한다.
- [ ] Show input wires OFF는 입력 선을 숨긴다.
- [ ] Show result OFF는 원본 표시로 돌아가며 ON으로 다시 결과가 표시된다.
- [ ] B를 A 밖으로 이동하면 A 전체가 결과로 남는다.
- [ ] B가 A를 완전히 감싸면 `Empty`이고 이전 결과가 남지 않는다.
- [ ] B를 Rhino에서 삭제하면 Missing/실패 상태와 마지막 정상 결과가 주황색으로 표시된다.
- [ ] 삭제 Undo 후 정상 결과가 복구된다.
- [ ] Remove로 등록을 해제해도 Rhino 원본은 삭제되지 않는다.

## 문제 보고와 제한

문제가 있으면 동작 순서, 패널 상태와 화면, `MTreeStatus` 출력을 기록합니다.
자동 갱신 문제는 재현 직전에 `MTreeTrace` ON → 조작 → OFF → `MTreeDumpLog` 출력도 기록합니다.

화면 없는 검사 호스트의 직접 Redo 호출은 플러그인 없는 기준 검사에서도 실패하므로 실제 Rhino에서 Undo/Redo를 확인해야 합니다.
트리 구성은 저장되지 않으며 트리 편집 자체는 Undo 대상이 아닙니다. 결과는 미리보기로, 결과 자체를 선택하거나 이동하는 기능은 아직 없습니다.
