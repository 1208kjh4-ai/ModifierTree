# 0.6.0 이동 중 Boolean 미리보기

작업을 저장하고 Rhino를 재시작한 뒤 `artifacts/bin/0.6.0/Release/net8.0-windows/ModifierTree.rhp`를 로드합니다. `MTreeStatus`에서 `0.6.0.0`을 확인합니다.

## 확인할 동작

1. 겹치는 Box A/B를 Difference 자식으로 넣습니다.
2. B 선택 → 패널 Move → 기준점을 지정합니다. 도착점을 확정하기 전에 마우스를 움직이면 모서리와 함께 최종 결과의 잘리는 위치도 바뀌어야 합니다.
3. 마우스를 멈추고 잠시 기다리면 마지막 위치의 결과가 표시되어야 합니다. Esc를 누르면 원래 결과로 돌아와야 합니다.
4. Select in Rhino → 기본 Move에서도 같은 동작을 확인합니다. 이어 Gumball로 B를 드래그합니다.
5. B를 A 밖으로 이동하면 A가 남고, B가 A를 완전히 감싸면 결과가 비어야 합니다. 다시 움직이면 결과가 복구되어야 합니다.
6. (A−B)−C 구조에서 B 또는 중간 Modifier를 이동하면 최상위 결과도 이동 중에 바뀌어야 합니다.
7. 전체 Modifier를 이동하면 하위 객체 간 상대 위치와 최종 형태가 유지되어야 합니다.
8. 위치 확정 후 Undo/Redo로 원본과 결과가 함께 복원되어야 합니다. 드래그 프레임마다 Undo 기록이 생겨서는 안 됩니다.

## 구현과 제한

임시 평가기는 원본의 복사본에 절대 이동값을 적용합니다. 드래그 프레임 사이에서 이동값을 누적하지 않습니다. 최종 결과와 임시 결과의 캐시를 분리하여 취소 시 원래 결과를 보존합니다.
UI 타이머와 패널 Move의 MouseMove 경로에서 계산하며 최소 간격은 80ms입니다. 이전 계산이 오래 걸리면 더 긴 간격을 사용합니다. 복잡한 Brep의 개별 Boolean 계산은 UI 스레드에서 실행되므로 지연이 있을 수 있습니다.
중간 계산 실패 시 마지막 정상 임시 결과를 남깁니다. 첫 임시 계산부터 실패하여 캐시가 없으면 기존 확정 결과를 사용합니다. 이동을 확정하면 현재 문서 원본으로 다시 평가합니다.

패널 Move는 전체 프레임 갱신을 켜며, 기본 Rhino Move/Gumball은 타이머에서 동적 변환을 조회하고 뷰를 다시 그립니다. 기본 명령의 실제 표시 루프는 사용자 화면에서 확인해야 합니다.
공식 [GetDynamicTransform](https://developer.rhino3d.com/api/rhinocommon/rhino.docobjects.rhinoobject/getdynamictransform)을 사용합니다. 모서리만 표시하는 기존 정책은 유지합니다.

자동 검사: Core/GUID 30개, Rhino·문서·레이아웃 89개 통과. 새 검사 12개는 임시 위치에서의 중첩 계산, 절대 변환, 중복 계산 생략, 빈 결과, 실패 복구, 전체 이동, 원본·Undo 보존, 취소와 재시작을 검증합니다.
이 검사는 임시 변환값을 직접 전달한 엔진 검사이며 실제 마우스 이벤트나 GPU 프레임 갱신을 완료한 것으로 간주하지 않습니다.
