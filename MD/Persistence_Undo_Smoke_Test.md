# 0.9.0 저장·복원 및 트리 Undo/Redo 확인

2026-09-09 사용자 확인: 저장 후 트리 유지, 트리 배치와 객체 이동을 섞은 Undo/Redo의 기본 동작이 정상임을 확인했습니다. 아래는 0.9.0 도입 당시 확인 절차입니다.

## 업데이트

기존 Rhino 작업을 저장하고 Rhino를 완전히 종료한 뒤 프로젝트 폴더에서 실행합니다.

```powershell
cd D:\Project_Modifier
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-plugin.ps1
```

Rhino를 다시 시작해 `MTreeStatus`의 버전 `0.9.0.0`을 확인합니다. 이미 등록한 플러그인이므로 버전 폴더의 `.rhp`를 다시 드래그하지 않습니다. 설치 스크립트는 고정 설치 경로를 갱신하고 기존 파일을 백업합니다.

0.8.0 이하에는 트리 저장 기능이 없었습니다. 이전 버전에서 구성한 트리는 파일에 남아 있지 않으므로 이번 업데이트 후 한 번 구성하고 저장해야 합니다.

## 저장하고 다시 열기

1. 새 문서에서 겹치는 닫힌 Box 세 개를 만들고 이름을 A, B, C로 지정합니다.
2. Add Object로 세 객체를 등록하고 Boolean Difference 두 개를 추가합니다.
3. 아래처럼 중첩합니다. C는 내부 Difference의 남은 부분과 겹치게 배치합니다.

```text
Boolean Difference
  Boolean Difference
    A
    B
  C
```

4. B의 InputWire를 켜고 C는 끕니다. 선택을 해제해 지속적인 표시 상태를 확인합니다.
5. `Save As`로 `.3dm` 파일을 저장합니다. 일반 저장 옵션의 사용자 데이터 저장을 유지합니다.
6. Rhino를 종료하고 다시 시작한 뒤 저장한 파일을 엽니다. 가능하면 `MTree` 명령을 실행하기 전에 파일부터 열어 플러그인 자동 로드도 확인합니다.
7. `MTree`에서 중첩 관계와 순서, A/B/C 이름, InputWire 설정 및 결과 형상을 확인합니다. 원본이 모두 존재하면 `Missing`이 나타나지 않아야 합니다.
8. 내부 Modifier에 들어가 B를 검볼로 이동합니다. 상위 결과까지 다시 계산되어야 합니다.
9. Show result를 끄고 저장·다시 열기를 반복합니다. 꺼진 설정이 유지되어야 합니다. 다시 켜면 결과가 계산되어 표시되어야 합니다.

추가로 빈 일반 문서를 열면 이전 파일의 트리가 남지 않는지 확인합니다. 모든 트리 행을 Remove한 상태로 저장·다시 열었을 때도 빈 상태여야 합니다. 트리가 들어 있는 파일을 Import하거나 Insert할 때는 현재 문서의 트리를 그대로 유지하며 가져온 트리를 합치지 않습니다.

미리보기 자체는 Rhino 결과 객체로 저장하지 않습니다. 저장된 원본과 트리에서 재계산합니다. 현재 선택, 내부 편집 진입 위치, 행 접힘 상태와 Undo 기록은 파일에 저장하지 않습니다.

## 트리 편집을 되돌리기

각 단계에서 변경 직후 `Undo` 한 번, `Redo` 한 번을 실행해 변경 전후가 정확히 복원되는지 확인합니다. 화면 갱신을 기다린 뒤 다음 작업을 진행합니다.

| 작업 | Undo 결과 | Redo 결과 |
|---|---|---|
| Add Object로 여러 원본을 한 번에 등록 | 이번 등록 전체 해제, Rhino 원본은 유지 | 같은 원본들이 다시 등록 |
| Add Modifier | 추가한 빈 Modifier 제거 | 같은 Modifier 복원 |
| 자식 B/C 순서 변경 | 원래 순서와 계산 결과 | 변경한 순서와 계산 결과 |
| 원본이나 중첩 Modifier를 다른 부모로 드래그 | 원래 부모와 위치 | 변경한 부모와 위치 |
| Drop here to move to root | 원래 부모 아래로 복귀 | 루트로 이동 |
| 원본 행 Remove | 같은 위치로 등록 복구 | 등록 해제 |
| Modifier 행 Remove | Modifier와 원래 자식 관계 복구 | 자식들을 상위로 꺼내고 Modifier 제거 |
| InputWire / Show result 변경 | 이전 표시 설정 | 바뀐 표시 설정 |

같은 위치에 드롭하거나 이미 등록한 원본만 다시 Add Object하면 불필요한 Undo 단계가 생기지 않아야 합니다. 저장 직후 트리만 수정해도 문서가 수정된 상태가 되어야 하며, 저장 후 다시 열기만으로 새 Undo 기록이나 수정 표시가 생기면 안 됩니다.

## 원본 편집과 섞어서 연속 실행

1. 구성된 트리에서 원본 C를 Rhino Move 또는 검볼로 이동합니다.
2. 패널에서 C의 부모나 순서를 변경합니다.
3. B의 InputWire 설정을 변경합니다.
4. `Undo`를 세 번 실행합니다. 표시 설정 → 트리 배치 → C의 위치 순서로 돌아가야 합니다.
5. `Redo`를 세 번 실행합니다. C의 위치 → 트리 배치 → 표시 설정 순서로 다시 적용되어야 합니다.
6. Undo/Redo를 한 차례 더 반복해 트리, 원본 위치와 최종 결과가 일치하는지 확인합니다.
7. 원본 B를 Rhino에서 삭제합니다. 트리에 `Missing`이 남고 결과가 누락을 알려야 합니다. Undo로 B를 복구하면 동일 등록에 다시 연결되고 결과가 정상으로 돌아와야 합니다.

새 편집을 한 뒤에는 Rhino의 일반 규칙대로 이전 Redo 분기가 사라집니다. 트리 배치 변경 시 선택과 내부 편집 범위는 초기화됩니다. 표시 설정만 바꾸는 경우에는 선택이나 Boolean 계산 캐시를 초기화하지 않습니다.

## 자동 검증 범위

2026-09-08, Rhino 8.34.26223.11001 / .NET 8, Release 빌드 오류·경고 0개. Core 검사 67개와 Rhino 검사 154개, 총 221개가 통과했습니다.

- 저장 상태의 동일성, 순서·노드 ID·원본 GUID·표시 설정 보존, 잘못된 버전·순환·중복·제한 초과 거부를 검사했습니다.
- 실제 네이티브 바이너리 아카이브를 쓰고 읽었습니다. 같은 아카이브를 객체 사용자 사전에 넣은 `.3dm`을 저장·다시 읽어 형상 GUID와 이름을 연결하고, 복원된 트리의 Boolean 결과까지 검사했습니다. 이 검사는 플러그인 파일 훅 및 자동 로드를 대신하지 않습니다.
- 원본 묶음 등록, Modifier 추가·삭제, 순서 변경, 표시 설정의 단일 네이티브 Undo, 기존 명령 Undo 기록에 합류, 변경 없는 작업 생략, 로드 시 문서 수정 표시 방지와 종료된 세션 처리를 검사했습니다.
- 화면 없는 Rhino 호스트에서는 플러그인 없는 형상 이동 기준 검사도 첫 Undo 이후 `UndoActive=True`로 남아 두 번째 Undo 및 Redo가 실패했습니다. 해당 분기는 건너뛰었으므로 실제 Rhino의 연속 Undo/Redo와 파일 열기 전체 경로는 위 절차로 확인해야 합니다.

## 저장 정책과 구현 위치

일반 Save/Save As와 전체 문서 템플릿의 트리를 지원합니다. Export Selected, 형상만 저장, 사용자 데이터 저장을 끈 저장에서는 트리를 제외합니다. Import/Insert/참조 파일 읽기는 활성 문서의 트리를 대체하지 않습니다.

알 수 없는 버전이나 잘못된 JSON을 만났을 때, 바이너리 사전 자체를 읽을 수 있으면 원본 사전을 보관하여 재저장합니다. 이때 트리 편집은 비활성화하고 이유를 Rhino 명령 기록과 패널 툴팁에 표시합니다. 바이너리 데이터도 읽지 못해 원본을 보존할 수 없으면 저장 오류를 보고합니다.

`TreeStateCodec`은 버전이 있는 불변 상태와 검증을, `TreeArchive`는 Rhino 바이너리 저장을, `TreeDocumentData`는 상태 변경과 Undo의 반대 상태 등록을 담당합니다. `DocumentSession`은 파일 읽기와 Undo/Redo가 끝난 후 Idle에서 선택·미리보기를 갱신합니다. Undo 콜백에서는 플러그인 내부 상태만 변경합니다. 이 구조는 McNeel의 [플러그인 문서 데이터 안내](https://developer.rhino3d.com/en/guides/rhinocommon/plugin-user-data/)와 [Custom Undo 예제](https://developer.rhino3d.com/samples/rhinocommon/custom-undo/)를 따릅니다.
