# 0.8.0 — 실시간 미리보기 계산 최적화

## 변경 사항

- 이전에는 계산 완료 후 `max(80ms, 계산 시간)`을 추가 대기했습니다. 이제 계산 시작을 기준으로 33ms 간격을 목표로 합니다. 16ms UI 타이머와 실제 계산·그리기 비용 때문에 30fps를 보장하지는 않습니다.
- 드래그 시작 시 확정 평가 결과를 복제해 임시 캐시를 만듭니다. 이후 원본 변환값이 달라진 노드와 그 상위 Modifier만 재평가합니다. 영향을 받지 않은 가지는 기존 결과를 유지합니다.
- 하위 원본 모두에 같은 평행이동이 적용된 Modifier는 확정 결과의 복사본을 이동시킵니다. 결과가 빈 경우도 그대로 재사용합니다. 중첩 Modifier가 이동하면 그 내부 Boolean은 생략하고, 움직이지 않은 형제와 만나는 부모는 재평가합니다.
- 변환값은 드래그 시작 형상에 대한 절대값입니다. 이전 프레임에 변환을 누적하지 않습니다. 이동 대상이 바뀌거나 변환 목록에서 빠진 원본도 다시 평가합니다.
- 회전·확대·비균등 변환에는 평행이동 전용 재사용을 적용하지 않습니다. 움직이지 않은 가지의 재사용은 유지합니다.
- 원본 변경·확정 재계산·트리 Revision·허용오차 변경은 캐시를 무효화합니다. 이동 취소는 임시 캐시만 버립니다. 실패 시 마지막 유효 결과를 남기는 기존 처리를 유지합니다.

## 측정 결과

2026-09-08, 설치된 Rhino 8.34 엔진, Release, 화면 없는 검사 호스트에서 측정했습니다. 원본 상자 7개로 `(A-B)-C`와 별도 Difference 2개를 구성했습니다. 전체 평가에는 Boolean 연산 4개가 있습니다. 경로별 준비 프레임 1회 후 20개 위치를 측정했고, 각 위치에서 기존 전체 평가와 최적화 평가의 결과 조각 수·부피·경계 범위를 비교했습니다.

| 이동 종류 | 전체 평가 중앙값 | 최적화 중앙값 | 20회 Boolean 호출 수 |
|---|---:|---:|---:|
| 최상위 Modifier 전체 평행이동 | 39.625ms | 0.328ms | 80 → 0 |
| 내부 Cutter B 이동 | 39.308ms | 16.567ms | 80 → 40 |
| 중첩 Modifier A/B 함께 이동 | 36.938ms | 12.142ms | 80 → 20 |

이는 타이머 대기·뷰포트 그리기를 제외한 테스트 형상의 계산 시간입니다. 복잡한 곡면이나 실제 사용자 모델의 속도로 일반화하지 않습니다. 준비 프레임의 캐시 복사 비용은 중앙값에서 제외했지만, 별도 검사로 첫 전체 이동 프레임도 확정 캐시가 있으면 Boolean 호출 0회임을 확인했습니다. 전체/부분 이동뿐 아니라 변환 제거, 빈 결과 복구, 고정 입력 변경, 오래된 트리 캐시 거절, 허용오차 변경도 검사했습니다.

자동 검사: Core/GUID 39개 + Rhino 121개 = 160개 통과. 빌드 오류·경고 0개. 직접 Redo API는 기존 화면 없는 기준 호스트에서도 실패하여 실제 Rhino 확인 대상으로 유지합니다.

재현:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1 -Configuration Release
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-rhino.ps1 -Configuration Release
```

출력의 `BENCH whole`, `BENCH cutter`, `BENCH nested`를 확인합니다. 시간 자체는 시스템 상태에 따라 달라지므로 시간 임계값으로 검사를 실패시키지 않으며, 결과 일치와 Boolean 호출 수를 검사합니다.

## 설치와 화면 확인

작업을 저장하고 Rhino를 종료한 뒤 프로젝트 루트에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-plugin.ps1
```

1. Rhino 재실행 후 `MTreeStatus`에서 `0.8.0.0`을 확인합니다. 세션 전용 트리를 다시 구성합니다.
2. 결과를 한 번 클릭해 최상위 Modifier를 검볼로 이동합니다. 모양과 A/B 상대 위치가 유지되며 더 부드럽게 이동하는지 확인합니다.
3. 이동 확정 후 `MTreeStatus`의 `Last live update`와 `Boolean`을 확인합니다. 유효한 전체 평행이동은 `Boolean 0`이 기대값입니다. 시간은 마지막 계산만 측정하며 그리기 비용은 제외합니다.
4. 더블클릭으로 내부에 들어가 B만 이동합니다. A는 고정되고 차집합은 계속 갱신되어야 합니다. 별도 Modifier를 추가해도 그 가지의 Boolean 호출이 더해지지 않아야 합니다.
5. `(A-B)-C`에서 A/B를 담은 자식 Modifier를 함께 이동합니다. A/B 내부 모양은 유지하고 C와의 차집합만 다시 계산해야 합니다.
6. 이동 중 Esc, 확정 후 Undo/Redo, 입력 교체·삭제·복구, 트리 순서 변경 후 다시 이동을 확인합니다. 이전 위치나 이전 트리 결과가 남지 않아야 합니다.
7. 전체/부분 Scale·Rotate도 확인합니다. 평행이동과 달리 Boolean 호출은 발생하지만 결과는 실제 변환을 따라야 합니다.

기본 선택과 검볼 확인은 [선택 화면 확인 순서](Viewport_Selection_Smoke_Test.md)를 함께 사용하되 설치 버전은 0.8.0을 기준으로 합니다.
