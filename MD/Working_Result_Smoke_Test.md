# 작업용 결과 · 스냅 · 내부 편집 확인 — 0.14.0

Rhino 작업을 저장하고 Rhino를 종료한 뒤 프로젝트 루트에서 아래 명령을 실행한다. 재시작 후 `MTreeStatus`의 버전이 `0.14.0.0`인지 확인한다. 기존 등록이 있으면 다른 폴더의 RHP를 추가로 드래그하지 않는다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-plugin.ps1
```

Release 파일은 `artifacts/bin/0.14.0/Release/net8.0-windows/ModifierTree.rhp`이고, 설치 스크립트는 고정 설치 폴더를 갱신한다. 검증용 문서를 따로 만들고 아래 항목을 진행한다.

## 1. 숨겨진 원본 대신 최종 결과에 스냅

1. Box A를 `(0,0,0)`에서 `(20,20,20)`까지, Box B를 `(8,-5,8)`에서 `(14,10,25)`까지 만든다. 두 객체를 등록하고 Boolean Difference 아래에 A, B 순서로 넣는다. 처음에는 두 InputWire를 OFF로 둔다.
2. 최종 결과만 표시되어야 한다. 트리에 넣지 않은 Line이나 Box도 옆에 하나 두고, 이 일반 객체의 표시·선택·스냅은 기존대로 작동하는지 확인한다.
3. End 스냅을 켜고 `Point` 또는 `Line` 명령에서 Boolean으로 새로 생긴 모서리 끝점 `(8,0,8)`에 스냅한다. 원본에는 없었던 교차점이므로 최종 Brep을 기준으로 잡혀야 한다. 만들어진 점의 좌표를 확인한다.
4. B의 원래 끝점 `(8,-5,8)` 부근에 커서를 댄다. 화면에 없는 Cutter 끝점이 End로 잡히면 안 된다. Near도 켜고 차집합으로 잘려 나간 A의 원래 위쪽 모서리 `(10,0,20)` 부근을 검사한다. 최종 결과에 없는 원본 선분에 Near가 잡히면 안 된다. 충분히 확대하여 주변의 실제 결과 모서리와 구분한다.
5. 최종 결과의 남은 모서리는 Near로 잡혀야 한다. End·Near를 하나씩 켜서 어떤 스냅이 선택되는지 확인한다.
6. Cen은 원형 모서리가 있는 별도 결과로 검사한다. Box를 위아래로 관통하는 Cylinder를 Cutter로 사용하고, 최종 구멍의 원형 모서리 중심에 Cen이 잡히는지 확인한다. 결과에 남지 않은 Cylinder의 원래 위·아래 원 중심이 스냅을 방해하면 안 된다.
7. 결과를 한 번 클릭하거나 창으로 선택하면 작업용 결과가 선택되고 기본 검볼이 나타나야 한다. 숨겨진 B가 함께 선택되거나 B의 바운딩 박스 때문에 검볼 중심이 불필요하게 멀어지면 안 된다.

스냅은 작업용 Rhino Brep이 제공한다. 실제 마우스의 스냅 표식과 명령에서 확정한 좌표를 함께 확인하며, 단순히 참고 선이 보이는지만으로 통과 처리하지 않는다.

## 2. InputWire는 참고 표시만 변경

1. 일반 작업 상태에서 B의 InputWire 셀을 더블클릭하여 ON으로 바꾼다. B의 참고 선이 보여야 한다.
2. 앞 절의 B 끝점 `(8,-5,8)`과 최종 결과에 없는 B 모서리에 End·Near를 다시 시도한다. 선은 보여도 이 원본에 스냅하거나 일반 선택하면 안 된다.
3. InputWire를 OFF로 바꾸면 참고 선만 사라져야 한다. 최종 결과의 선택·스냅·검볼은 그대로 유지되어야 한다.
4. InputWire 변경을 Undo/Redo한다. 선 설정이 복원되고, 이 작업만으로 내부 편집에 진입하거나 원본이 노출되면 안 된다.

## 3. 내부 편집과 중첩 범위

1. 최종 결과를 더블클릭한다. Difference가 `Editing` 상태가 되고 바로 아래 A, B를 모서리로 볼 수 있어야 한다. 이 단계에서는 A, B와 최종 결과에 스냅할 수 있어야 한다.
2. B만 선택해 Move 또는 검볼로 이동한다. A는 제자리에 있고 차집합 결과만 갱신되어야 한다. 이동 중 B는 모서리로 표시되어야 한다.
3. 명령을 끝내고 Esc 또는 빈 공간 더블클릭으로 한 단계 나온다. A, B는 다시 숨겨지고 최종 결과만 선택·스냅 대상으로 남아야 한다. InputWire가 ON이라 참고 선이 남아 있더라도 원본 스냅은 다시 제외되어야 한다.
4. 일반 작업 상태에서 패널의 B 행을 선택한 뒤 **Select in Rhino**를 누른다. B의 부모인 Difference 편집 단계로 자동 진입하여 B를 선택하고 검볼을 표시해야 한다. Name 셀 더블클릭은 기존처럼 이름 편집을 실행해야 한다.
5. 상위 Boolean Union 아래에 Difference와 Mirror 또는 Array를 배치한다. 최상위에서는 최종 결과만, Union 내부에서는 바로 아래 Modifier 결과만 선택·스냅되어야 한다. 그 아래의 원본은 더블클릭으로 해당 단계에 들어갈 때까지 숨긴다.
6. Mirror 내부로 들어가 BasePlane을 선택한다. 이 단계에서만 평면을 조작·스냅할 수 있어야 하며, 평면의 Move·Rotate로 대칭 결과가 갱신되어야 한다. 상위 단계로 나오면 BasePlane은 다시 숨겨져 스냅을 방해하지 않아야 한다.
7. 다른 원본을 사용자가 직접 Hide한 경우, 내부 편집에 진입하거나 Show result를 껐다는 이유로 그 Hide를 해제하면 안 된다. 사용자 잠금과 레이어 잠금도 유지해야 하며 해당 원본을 포함한 전체 변환은 거부되어야 한다.

## 4. 결과 전체 변환과 Undo/Redo

1. 내부 편집에서 완전히 나온 뒤 Difference 결과를 한 번 클릭하고 Rhino **Move**를 실행한다. 결과와 모든 하위 원본이 같은 거리만큼 이동해야 하며, 숨긴 원본이 잠깐 선택되거나 화면에 드러나면 안 된다.
2. 같은 조작을 기본 검볼의 이동·회전 핸들로 확인한다. 드래그 중 결과가 유지되고 마우스를 놓은 위치에서 확정되어야 한다. Esc 취소는 원본·결과·설정을 이전 상태로 되돌려야 한다.
3. Array의 결과 전체를 Rotate로 90도 돌린다. 원본뿐 아니라 축도 함께 돌아 배열 전체가 회전해야 한다. 내부 편집으로 들어가 원본만 회전했을 때에는 Array 축이 유지되어야 한다.
4. Mirror 전체와 Mirror를 포함한 상위 Modifier를 각각 회전한다. 원본과 BasePlane이 함께 이동하여 전체 결과가 같은 변환을 받아야 한다. Mirror에 중첩된 Array가 있으면 그 축도 따라가야 한다.
5. 각 확정 변환 직후 Undo를 한 번 실행한다. 원본 위치, BasePlane, Array 축·간격과 결과가 함께 복원되어야 한다. Redo도 확인하고 Move → Rotate → Undo → Undo → Redo → Redo를 연속으로 수행한다.
6. 서로 독립된 최상위 결과 두 개와 일반 Rhino 객체 하나를 함께 선택하고 Move·Rotate한다. 모두 정확히 한 번씩 변환되어야 하며 한 번의 Undo로 함께 복원되어야 한다.
7. 내부 편집에서 최종 결과와 노출된 입력을 동시에 선택하여 회전하는 경우, 입력이 두 번 변환되지 않아야 한다. 최종 결과의 전체 변환과 일치하는지 확인한다.

## 5. 저장·닫기·다시 열기

1. Mirror와 Array, 이름, 사용자 지정 축, InputWire ON/OFF가 섞인 트리를 준비한다. 원래 사용자 Hide·잠금이 있는 별도 객체도 남긴다.
2. 일반 Save와 Save As를 각각 실행한다. 저장 후 최종 결과가 다시 표시되고, 원본이 노출된 채 남거나 결과가 중복되면 안 된다. 저장만 했는데 작업용 객체 재생성 때문에 문서가 다시 수정된 상태가 되면 안 된다.
3. 저장한 파일을 닫고 다시 연다. 트리와 원본 GUID, BasePlane, 축·간격·Union 설정을 복원하고 같은 최종 결과가 한 번만 표시되어야 한다. 평소 원본 스냅이 차단되는지도 다시 검사한다.
4. 내부 편집 중인 상태에서도 저장하고 다시 연다. 편집 범위는 일반 작업 상태로 시작하며, 원본이 영구 Hide로 저장되어 편집할 수 없게 되면 안 된다.
5. Show result를 끄면 작업용 결과가 사라지고 원본의 기존 표시·잠금 상태로 돌아와야 한다. 사용자가 원래 Hide한 객체는 계속 숨겨져 있어야 한다. 다시 켜면 최종 결과와 현재 편집 범위에 맞게 표시·스냅을 복원한다.

일반 `.3dm` 저장 직전에는 `BeginSaveDocument`에서 작업용 객체를 제외하고 원본 표시 모드를 복원한다. 저장이 끝난 뒤 Idle에서 작업용 결과를 다시 만든다. 원본과 트리는 저장하지만 파생된 작업용 결과는 영구 객체로 남기지 않으며, 저장 형식은 기존 **schema 4**를 유지한다.

## 6. Bake·Merge·Copy

1. Mirror 결과를 Bake한다. 고정 Brep이 루트에 추가되고 원래 트리도 유지되어야 한다. BasePlane의 위치·방향·크기는 바뀌면 안 된다. Bake 결과만 이동하면 원래 Mirror와 BasePlane은 그대로 있어야 한다.
2. Mirror를 Merge한다. 해당 트리 위치가 고정 Brep으로 교체되고 원래 BasePlane과 입력은 같은 위치에 숨겨져 있어야 한다. BasePlane의 면이 Merge 결과에 포함되면 안 된다.
3. Merge를 Undo/Redo한다. 원래 트리와 BasePlane, 최종 결과를 정확히 복원하고 작업용 Brep이 중복되면 안 된다. Merge 결과만 이동해도 원래 BasePlane은 움직이면 안 된다.
4. 일반 작업용 결과를 선택하고 Rhino **Copy**를 실행한다. 복사본은 트리와 연결되지 않은 고정 Brep이어야 한다. 원래 입력을 편집했을 때 원본 작업용 결과만 갱신되고 복사본은 그대로 있어야 한다.
5. Copy한 Brep은 자동으로 트리에 추가되지 않아야 한다. 필요하면 **Add Object**로 등록하여 다른 Modifier의 입력으로 사용할 수 있어야 한다. 트리까지 복제하는 **Duplicate subtree**와 구분하여 확인한다.

작업용 결과는 트리에서 다시 생성된다. 결과에 직접 Trim·Boolean·면/모서리 편집을 적용하는 사용 방식까지 지원하는 것은 아니므로, 이러한 형상 변경은 먼저 **Bake 또는 Merge**한 고정 결과에 수행한다. Copy로 만든 독립 Brep에도 일반 Rhino 형상 편집을 적용할 수 있다.

## 검증 기록

- 2026-09-11 최종 Release 빌드: 경고·오류 0개, **Core 172개 + Rhino 591개 = 763개 검사 통과**. [빌드 로그](../artifacts/validation/0.14.0/release-build-2026-09-11.txt), [Rhino 검사 로그](../artifacts/validation/0.14.0/rhino-checks-2026-09-11.txt).
- 별도 네이티브 명령 검사 26개와 전체 DocumentSession 연동 검사 35개도 통과했다. 실제 Move·Rotate·Undo/Redo, 저장 훅, Copy·Merge·편집 범위를 확인했다. 이 61개는 마지막 저장 보호·Hide 선택 보완 이전의 통합 검증이며, 최종 주 검사 763개와 별도로 집계한다.
- 기존 화면 없는 호스트에서 지원하지 않는 연속 Undo/Redo 관련 3개 SKIP은 별도로 남는다. 네이티브 명령 검사에서 Undo/Redo를 확인한 것과 이 호스트 제한을 혼동하지 않는다.
- 실제 마우스의 End·Near·Cen 스냅, 검볼 표시·핸들 드래그, 더블클릭 진입·Esc 복귀, 저장 후 Rhino 재시작은 위 수동 확인이 필요하다.

추가 확인: 결과를 Rhino Hide로 숨긴 뒤 그 위치를 클릭·더블클릭하거나 다른 결과를 움직여도 숨긴 결과가 표시되거나 선택되지 않아야 한다. Show로 복구하면 다시 표시·선택할 수 있어야 한다. Export Selected로 내보낸 결과는 새 파일에서 일반 Brep으로 열리고 Add Object로 등록할 수 있어야 한다.
